Vivado block design connections — swiglu_0 (current q4k_final bitstream)
Addresses: docs/vivado_addresses.txt (swiglu) and hls_experiments/testblock/addresses.txt
(testblock).

zynq_ultra_ps_e_0
- M_AXI_HPM0_FPD → axi_smc S00_AXI
- S_AXI_HP0_FPD  ← smartconnect_0 M00_AXI
- S_AXI_HP1_FPD  ← smartconnect_1 M00_AXI
- S_AXI_HP2_FPD  ← smartconnect_3 M00_AXI
- pl_ps_irq0     ← xlconcat dout

axi_smc (AXI-Lite control)
- M00_AXI → swiglu_0 s_axi_CTRL
  (an earlier revision of this file also listed M02_AXI, left over from the 4-peripheral
  DMA design; the M00 entry is the one updated with the testblock. The port index does
  not affect the address map — confirm in the .bd if it matters.)

swiglu_0 / testblock
- s_axi_CTRL     ← axi_smc M00_AXI
- interrupt      → xlconcat In0   (pl_ps_irq0[0] = GIC SPI 121 = DT `<0 89 4>`, pl.dtsi)
- m_axi_gmem_W   → smartconnect_3 S00_AXI → HP2
- m_axi_gmem_Wd  → smartconnect_1 S00_AXI → HP1
- m_axi_gmem_V   → smartconnect_0 S00_AXI → HP0
- m_axi_gmem_out → smartconnect_0 S01_AXI → HP0
- m_axi_gmem_x   → smartconnect_0 S02_AXI → HP0

So W_gate (HP2) and W_up (HP0) stream over separate HP ports during the overlapped
X1 ∥ X2 stage; W_down has HP1 to itself. HP0 also carries the two small x/out transfers.


BOARD CONFIGURATION
udmabuf: 512 MiB (`insmod u-dma-buf.ko udmabuf0=536870912`, scripts/deploy/deploy-fabric.sh).
It fits the board's effective CMA pool without editing the boot script; see
docs/udmabuf_info.txt.
