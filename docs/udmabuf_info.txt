u-dma-buf on the KV260 — sizing and CMA
(revised 2026-10-03; the earlier version documented a 640 MB buffer that is no longer used)

CURRENT SETUP
- ggml-cpu.c: UDMABUF_SIZE = 536870912 (512 MiB).
- Load (each boot, done by scripts/deploy/deploy-fabric.sh step [7]):
     cd ~/udmabuf && sudo insmod u-dma-buf.ko udmabuf0=536870912
  The module is built from source in ~/udmabuf; it is not in /lib/modules.
- Verify:
     cat /sys/class/u-dma-buf/udmabuf0/phys_addr   -> valid physical address
     cat /sys/class/u-dma-buf/udmabuf0/size         -> 536870912
  Captured on the q4k_final run (hls_experiments/q4k_final/clipboard_q4k.txt):
  phys_addr 0x55100000, size 536870912.

What lives in the buffer (offsets from llama-mods/ggml-cpu.c):
  0x00000000                    x (INT8, 2048 B)
  0x00010000                    out (FP32, 8192 B)
  0x01000000 + l × 0x01E00000   layer l slot (l = 0..15), 30 MiB each:
                                W at +0, V at +0xA00000, W_down at +0x1400000
  Layer 15 ends at 0x1F000000 (496 MiB).
_Static_asserts next to the defines fail the build if any two regions overlap. Until
2026-10-04, x and out sat at 0x06C50000 and 0x06C60000, inside layer 3's W slot
(README.md, "Driver bugs").

CMA
The stock Kria boot script (/boot/firmware/boot.scr.uimg) sets cma=1000M and then
appends cma=600M. The kernel uses the last cma= value, so the effective pool is 600M. The
board's /proc/cmdline in clipboard_q4k.txt shows exactly this:
   ... cma=1000M quiet splash cma=600M
512 MiB fits within 600M, so no boot-script edit is needed.

IF THE BUFFER EVER NEEDS TO EXCEED ~600 MB
Symptoms:
  dmesg: "u-dma-buf udmabuf0: dma_alloc_coherent(size=...) failed"
  dmesg: "u-dma-buf u-dma-buf.0: driver probe failed. return=-12"  (-12 = ENOMEM)
  /sys/class/u-dma-buf/udmabuf0/ does not exist after insmod; the driver then prints
  "Error: udmabuf0 phys_addr not found."
Fix (applied once, earlier in the project, for a 640 MB buffer): remove the trailing
cma=600M from the boot script so cma=1000M takes effect.
  1. dd if=/boot/firmware/boot.scr.uimg bs=64 skip=1 of=/tmp/boot.cmd
     (skip the 64-byte mkimage header)
  2. In /tmp/boot.cmd change
        setenv bootargs " ${bootargs} quiet splash cma=600M"
     to
        setenv bootargs " ${bootargs} quiet splash"
  3. mkimage -c none -A arm -T script -d /tmp/boot.cmd /tmp/boot.scr.uimg
     sudo cp /boot/firmware/boot.scr.uimg /boot/firmware/boot.scr.uimg.bak
     sudo cp /tmp/boot.scr.uimg /boot/firmware/boot.scr.uimg
  4. Reboot; /proc/cmdline should show only cma=1000M.
The q4k_final cmdline above shows cma=600M again, so this edit is not in place on the
board image used for the reported results.
